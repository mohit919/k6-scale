# OSS extraction safety

This project should be developed as a clean-room, vendor-neutral framework.

Do not copy code, history, data, names, endpoints, headers, payloads, architecture diagrams, or business logic from a previous employer/client repository unless you have explicit rights to publish them.

Safe inputs are engineering ideas and generally applicable techniques: workload modelling, module boundaries, reusable configuration, executor selection, threshold policy, deterministic test-data allocation, CI validation, and documentation patterns.

Before publishing any repository derived from prior professional work, review the applicable employment/consultancy IP and confidentiality terms.
